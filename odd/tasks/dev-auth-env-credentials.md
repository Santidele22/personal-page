# Feature: Auth interino dev (credenciales en .env)

Objective: login de prueba sin Better Auth — credenciales hardcodeadas en el `.env` del usuario para probar la app completa; Better Auth queda intacto para reactivarse al final con `AUTH_MODE=better`.
Branch: `dev` en backend (base e13579d) y `dev` en root (base bf317fe). Tracking issue: Santidele22/personal-page#7; UAT issue después del middleware: #8.
Delivery: work-unit commits; runners pnpm (vitest backend / build+check frontend).

## Specs

- S1: "vamos a hardcodear en el .env las credenciales de acceso para probar" — el backend lee el `.env` en boot (carga en `main.ts` únicamente; los tests no leen `.env`); `AUTH_MODE=dev` con `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `DEV_SESSION_SECRET` habilita el login de prueba; credenciales nunca commiteadas ni logueadas.
- S2: "todavia no vamos a usar BETTER_AUTH ... a lo ultimo lo voy a agregar" — en modo dev el stack Better Auth NO se monta; en modo better (default cuando `DATABASE_URL` está seteado) el flujo actual funciona exactamente igual que hoy; el switch es solo `AUTH_MODE`.
- S3: endpoints dev: `POST /auth/dev-login` (validación timing-safe vs env), `GET /auth/dev-session` (snapshot o 401), `POST /auth/dev-logout`; cookie HttpOnly SameSite=Lax firmada con HMAC, expiración `DEV_SESSION_TTL`; endpoint público `GET /auth/session-mode` → `{ mode }` para que el frontend elija fuente.
- S4: guards en dev: mutaciones (POST/PUT/PATCH/DELETE) requieren sesión dev válida y responden 401 sin ella; `@AllowAnonymous` respeta lecturas/suscripciones públicas; en dev toda sesión valida es rol admin (única cuenta hardcodeada).
- S5 (frontend): `features/auth` selecciona fuente según `/auth/session-mode`: dev → endpoints nuevos con `getJson/postJson` (credentials include), better → better-auth client actual; mismo UX (gate, redirect, errores en español, logout). Sin dependencias nuevas en frontend.
- S6: verificación — backend: `pnpm lint|build|test|test:e2e` verde; suite nueva para el modo dev (login ok/err, cookie set/expirada, guard 401/201/200, logout, mode better intacto); frontend build/check/tsc verde; flujo real manual: login por proxy en un servidor real con env de prueba, dashboards visibles; `.env.example` — el usuario pega él mismo el bloque (permiso runtime lo bloquea).

## Tasks

- T1 (S1–S6) — DONE: dotenv en boot + módulo dev auth + guard + adaptación frontend + README + pruebas. Route: delegated (un solo worker acotado, ambas repos: superficie acoplada).

Feature cerrada. `Risk: none` en el estado final — los dos extento de riesgo detectados (parser de cuerpo ausente en boot Docker-less; secret HMAC vacío forjable) fueron corregidos, pinneados con tests y revisados por la review nativa (ACK, authority burned). Riesgo residual aceptado: el modo dev es interino y se reemplaza por Better Auth "a lo último" (AUTH_MODE=better).
