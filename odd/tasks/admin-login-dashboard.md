# Feature: Login + dashboard admin conectado al backend

Objective: login screen with Better Auth (email/password) and the admin dashboard consuming the backend API, replacing the hardcoded demo data feed-by-feed.
Branch: root repo `dev` (Santidele22/personal-page, base main+4) and backend repo `dev` (base master, commits: 7107185, f7139f3, 9f3a113, 65099a6).
Delivery: work-unit commits per repo (~400 lines); frontend runner: pnpm (personal-app); backend: pnpm (vitest).

## Specs

- S1: "creemos una rama dev y trabajemos desde ahi" — all work lands in each repo's `dev` branch, never on main/master.
- S2: "pantalla de login y todo el dashboard conectado al backend" — login page with Better Auth email/password client (`better-auth` dependency in personal-app matching backend 1.7.10), session-aware AdminLayout (sidebar/topbar show real session user, logout; unauthenticated admin visits redirect to login), and dashboards wired to real backend endpoints as they exist: publicidad (`/advertising-plans`, `/brands`), diario (`/blogs`), resumen (real aggregates over existing endpoints); nothing invented.
- S3 (mapping decisions): dev connectivity via vite `server.proxy` `/api` → `http://localhost:3000` in `astro.config.mjs`; backend `src/auth/auth.ts` gets `trustedOrigins` from env (`BETTER_AUTH_TRUSTED_ORIGINS`, comma-separated, localhost:4321 default) so sign-in works cross-origin too; `shared/api/http.ts` gains `credentials: 'include'` and GET support.
- S4 (FSD placement): auth feature in `src/features/auth/` (client factory + login island per existing islets pattern e.g. NewsletterForm.tsx), page at `src/pages/admin/login.astro`, session island consumed from AdminLayout; data transformation stays in `entities/admin` (types/adapter) — no deeper fetches in pages.
- S5 (backend data contract): mapping may only use fields that exist in backend entities/DTOs — frontend `AdminSlot`'s dimensions/position/impressions have NO backend counterpart and stay demo or get dropped in the wired view; suscriptores has NO backend module today. Recommended path: subscribe existing frontend form (`POST /newsletter/subscribe` with today's DTO) to a new backend `newsletter` module (admin-guarded list, public subscribe) in this feature as its own task; if done, its data feeds `/admin/suscriptores/` and the hardcoded demo ends — requires the user's approved scope.
- S6: verification — backend: `pnpm lint|build|test|test:e2e` green (unchanged-guarded suite; auth smoke still green against the local Postgres). Frontend: `pnpm build` (astro check) green; login flow verified against backend dev boot (sign-in on 4321 via proxy, session cookie set, protected admin redirects), CRUD reads render live data with graceful error states; no demo leftovers in wired views. DBeaver DB checks unchanged.
