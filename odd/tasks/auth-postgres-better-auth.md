# Feature: Postgres local + Better Auth

Objective: migrate backend persistence to a local PostgreSQL (testable with DBeaver) and adopt Better Auth as the owner of the identity model for authentication/authorization.
Branch: feat/better-auth-postgres (created over an initial bootstrap commit of the current backend state).
Delivery: work-unit commits (~400 lines), conventional commits; runner: pnpm (vitest).

## Specs

- S1: "vamos a usar typeorm como orm y postgresql como base de datos" — the app connects to PostgreSQL through `DATABASE_URL` (TypeORM `pg`); without `DATABASE_URL` it keeps today's SQLite fallback in tests (`better-sqlite3` in-memory) and local dev without Docker.
- S2: "quiero que usemos una base de datos local para ir probando y testeando los datos con dbeaver" — `backend/docker-compose.yml` runs `postgres:17-alpine` on `localhost:5432` with persistent volume, healthcheck and credentials documented in `.env.example` (`DATABASE_URL=postgres://...`); DBeaver connects with those credentials. The dev DB is started with `docker compose up -d`.
- S3: "vamos a usar better_auth para la autenticacion y autorizacion" — better-auth installed with its `pg` adapter pointing to the same `DATABASE_URL`; auth endpoints mounted in NestJS (`/api/auth/*`, `bodyParser: false` required); email/password enabled; admin plugin for authorization; env vars `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`.
- S4 (decision accepted in this session): "Better Auth es dueño" — its tables (`user`, `account`, `session`, `verification`) are created and migrated by better-auth (CLI), TypeORM does not synchronize them; the existing `User` entity reconciles to the better-auth user (id text, `synchronize: false`), domain relations (`Blog.author`, `Project.owner`, etc.) reference the better-auth user id, and the own bcrypt/password handling is removed.
- S5: no silent break: password never appears in JSON responses (kept); current CRUD keeps its public reads; mutations get admin-guarded once authorization is wired; every behavior change is a documented, requested change.
- S6: verification — `pnpm lint`, `pnpm build`, `pnpm test`, `pnpm test:e2e` green: CRUD e2e keeps running on SQLite in-memory; new auth smoke e2e runs against the local Postgres from S2 and skips when it is unavailable; unit specs keep mocking repos and updated for the users service without bcrypt.
