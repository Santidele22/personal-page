# Issue 45 — Portafolio: sección de certificados (backend + frontend)

Objective: new `certificates` module (backend admin CRUD + public read) and frontend (public portfolio section + admin editor panel), following the existing `tools`/`books` patterns.
Branch: `feat/issue-45` (from `main` @ 48c2145). Delivery strategy: `single-pr` (work-unit commits on this branch; the PR itself stays a user decision). Test runner: backend `pnpm test` (Vitest) in `backend/`; frontend `pnpm test` in `personal-app/` + `pnpm astro check` + `pnpm exec tsc --noEmit` + `pnpm build`.

## Specs

- S1: "El admin puede crear, editar, eliminar y listar certificados, con imagen opcional (un certificado sin imagen se muestra igual)." — backend admin CRUD (`@Roles(['admin'])` for create/update/delete, public `GET` anonymous), optional image mirroring the books multipart upload with magic-byte validation; a certificate without image is returned/stored fine without an image field value.
- S2: Entidad con los campos: imagen (opcional), título, descripción, link del lugar (plataforma/institución que emite el certificado), fecha, etc. (Entity: `image?`, `title`, `description`, `issuerLink`, `date`, mirroring the tool/book entity conventions.)
- S3: "Ordenar los certificados por fecha, del más reciente al más antiguo." — public `GET /certificates` returns rows ordered by date DESC; public section renders in that order.
- S4: "Las lecturas públicas siguen la misma estrategia de caché de contenido público definida en #44; el admin no se cachea." — add `'/certificates'` to `CACHEABLE_PATHS` in `personal-app/src/shared/api/contentCache.ts` (+ its test); admin reads go through `authorizedHttp.ts` bearer path which bypasses the cache. Cache invalidation is automatic via `pages/api/[...path].ts` mutation hook (no extra work).
- S5: "La sección pública muestra los certificados con todos sus campos y el link al lugar/certificado." — new public widget composing image (conditional), title, description, link, and date.
- S6: "Sin imagen cargada, la sección pública no muestra un placeholder roto." — render the image block only when the row has an image; no broken-image artifact.
- S7: "Un visitante anónimo puede leer los certificados, pero no puede crearlos ni modificarlos." — anonymous `GET` allowed (`@AllowAnonymous()`), mutations require admin role (pinned by backend spec test).
- S8: Frontend: sección de edición en el panel admin siguiendo el patrón de los editor panels existentes (por ejemplo, `ToolsEditorPanel`) — new `CertificadosEditorPanel` registered in `AdminSection` (`src/entities/admin/types.ts`), `AdminSidebar.astro` nav, and a new `src/pages/admin/*.astro` route.
- S9: "Builds/checks y pruebas de backend y frontend pasan." — backend `pnpm test`, frontend `pnpm test`, `pnpm astro check`, `tsc --noEmit`, `pnpm build` all green.

Scope guards (assumptions, marked as such): image is an uploaded file like books (multipart `FormData` + bearer), not an external URL field; entity has no `published` flag (nothing in the issue asks for draft semantics); fallback data is a small hardcoded sample in `entities/certificate/data.ts` mirroring `entities/tool/data.ts`.
