# Issue 47 — Paginación offset/limit + landing limit 4 + "Ver todos" con view transitions

**Objetivo:** paginar todos los GET de colección del backend (offset/limit, con total), limitar la landing a 4 ítems por sección con "Ver todos" hacia páginas dedicadas paginadas, y navegar con view transitions cross-document CSP-safe.
**Branches:** root (frontend) `feat/issue-47-pagination`; backend repo anidado `feat/issue-47-pagination`. Delivery: `ask-on-risk` (consultar estrategia de entrega al final).
**Test runners:** backend — `pnpm test` (vitest) en `backend/`; frontend — `pnpm test`, `pnpm astro check`, `pnpm exec tsc --noEmit` en `personal-app/`.

## Specs

Requisitos con las frases de la issue 47 citadas verbatim:

- **S1** (Backend): "Parametrizar paginación offset/limit en **todos los GET de colección**, públicos y admin: `certificates`, `books`, `blogs`, `projects`, `services`, `tools`, `menu-links`, `brands`, `advertising-plans`."
  - El dominio "menu-links" del backend real es `menu-items` (equivale al fetch `menu-links` del front).
  -(Incluye también los GET de colección admin restantes: `GET /blogs/drafts` y `GET /users`).
- **S2** (Backend): "Query params: `?offset=0&limit=N`, con defaults sensatos y un `limit` máximo (clamp) para que ningún parámetro devuelva la tabla completa sin querer." Definiciones: `offset` default `0` y clamp a `>= 0`; `limit` default `20`, clamp a `[1, 50]`; valores inválidos (`abc`, negativos, decimales) se rechazan con 400 o saneados sin error 500. Comprobación: "Con `offset`/`limit` inválidos o excesivos, el endpoint responde saneado (clamp) sin error 500."
- **S3** (Backend shape): "La respuesta debe incluir un `total` (o shape equivalente `items/total/offset/limit`) para que el front pueda paginar."
  - Decisión: **con query params**, respuesta envuelta `{ items, total, offset, limit }`; **sin query params**, array plano de siempre. Basado en el criterio S4: "sin query params, cada endpoint devuelve exactamente lo mismo que hoy". Regla: presence de `offset` o `limit` válidos (post-clamp) ⇒ envelope.
- **S4** (Compat, Backend): "Sin `query` params, cada endpoint devuelve exactamente lo mismo que hoy (diferencial contra la salida actual antes del cambio)." Diferencial contra commit base en todos los GET de colección (sin params), comparando stdout+exit code con copia del commit base.
- **S5** (Books, supuesto — asumido en base a la issue #47): hoy el front (`personal-app/src/features/book/api/books.ts:47`) filtra `published === true` client-side, y el backend `GET /books` devuelve borradores también. Para que "cada sección traiga solo el contenido que muestra" con `limit=4` server-side, se agrega query param opcional `published=true` en `GET /books`, que filtra servidor-side; sin él, byte-equivalente a hoy (S4 intacto). El front lo usa en landing y página dedicada.
- **S6** (Orden estable, Backend): "Tests: uno por regla nueva (parsing de params, clamp, orden estable con offset, `total` correcto)". Determinismo: en el camino paginado, cada dominio puede ofrecer ORDER BY determinista: los dominios con order natural hoy (certificates `date DESC`, blogs `pubDate Not(IsNull())`, menu-items `position,id`) lo conservan; los sin orden (books, projects, services, tools, brands, advertising-plans) obtienen `ORDER BY id ASC` solo en el camino paginado (no tocar el orden del camino sin params).
- **S7** (E2e existentes verde): los e2e que asumen array plano y params no se rompen: `test/projects-portada.e2e-spec.ts`, `test/services-portada.e2e-spec.ts`, `test/menu-items.e2e-spec.ts`, `test/brands.e2e-spec.ts`, `test/blogs-portada.e2e-spec.ts`, `test/advertising-plans.e2e-spec.ts`, `test/tools.e2e-spec.ts`, `test/books*.e2e-spec.ts`. Con params nuevos, responden `{items,...}`; sin params siguen array plano y los tests que comparan forma exacta deben seguir pasando sin tocarlos (excepto si algunos ya esperan `total` en otros paths, aflora como fallo y se ajusta el spec correspondiente).
- **S8** (Frontend landing): "Cada landing section llama a su API con `limit=4`, render server-side (página 1 pintada en HTML, sin waterfall)." Secciones: certificados, proyectos, lecturas (books+S5), servicios (según `showServicesOnLanding`). Comprobación: "La landing muestra máximo 4 ítems por sección, renderizado en el HTML inicial (verificar con `curl` el HTML server-rendered)."
  - Nota: Blog landing ya no se cuenta como sección limitada por la issue (it has its hero + curated slice); igual conserva su comportamiento actual.
- **S9** (Botones "Ver todos" + páginas dedicadas): "Botón **"Ver todos"** por sección que lleva a su propia página dedicada con el listado completo y paginación por query params (`/seccion/?offset=N`), server-rendered." Páginas nuevas siguiendo patrón `/marcas`/`/blog`: `/certificados`, `/proyectos`, `/lecturas`, `/servicios`; marcas ya tiene `/marcas` (reutilizar, paginar si hace falta según `offset/limit`); blogs ya tiene `/blog` — paginar el archivo. Comprobación: "\"Ver todos\" en cada sección navega a su página dedicada con el list completo y paginación funcional por URL; la página dedicada comparte y tiene estado real de carga/empty/error."
- **S10** (Accesibilidad + motion): "Botón "Ver todos"/"Volver" con accesibilidad decente y `prefers-reduced-motion` respetado."
- **S11** (View transitions CSP-safe): "Opción preferente CSP-safe: view transitions **cross-document nativas** (`<meta name="view-transition" content="same-origin">` + regla `@view-transition`, soportadas en Chromium), re-usando los `transition:name`/`view-transition-name` ya presentes en blogs (`blog-title-*`, `blog-hero-*`) y agregando equivalentes por sección (ej. `cert-card-{id}`)." Comprobación: "La animación de transición se observa realmente en el navegador (desktop y móvil) y se desactiva con `prefers-reduced-motion: reduce`." No tocar el CSP de `astro.config.mjs` ni des-reintroducir `ClientRouter`(lo removió issue 41).
- **S12** (Cache SSR): el cache SSR de `shared/api/contentCache.ts` por ruta: agregar al whitelist exacto las consultas fijas de la landing (ej. `/certificates?limit=4`, `/books?limit=4&published=true`, `/projects?limit=4`, `/services?limit=4`) para no perder el cache de la issue 44. Páginas dedicadas con `?offset=N` dinámicas: aceptado quedarse sin cache de SSR memo (estado previo a issue 44 para esas páginas nuevas); documentar en el log.
- **S13** (Fuera de alcance): "Cursor/keyset pagination (se justifica recién con cientos/miles de filas por tabla)." y "Infinite scroll / load more."
- **S14** (Checks finales): "`pnpm build`, `pnpm astro check` y `pnpm exec tsc --noEmit` pasan; revisión visual en dark mode incluida." (Además `pnpm test` backend y frontend verde.)
