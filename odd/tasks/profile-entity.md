# profile-entity

Objective: replace hardcoded landing/personal data with a DB-backed `profile` entity (backend CRUD `/profile`) editable from the admin panel. Issue #9.
Branches: root repo (personal-app, odd/) `dev` · backend repo (nested, no remote) `dev`.
Delivery strategy: `ask-on-risk` (default) · Test runner: backend vitest (unit + e2e), frontend `astro check` + dev-server smoke.

## Specs

User's exact strings from Issue #9 are quoted verbatim below.

- **S1 (backend) — profile entity + CRUD**: "entidad `profile` (Nest + TypeORM, CRUD en `/profile`, protegido por la composición de guards de la issue #6: mutaciones solo admin). Un perfil es un registro único o versionado — la forma exacta se decide al implementar." Decided shape: singleton row (`@Entity('profile')`, one row), `GET /profile` returns the row or built-in defaults (200 always), `PUT /profile` upserts (admin only). Columns dialect-portable (no Postgres-only types; arrays/objects as `json`): `name`, `role`, `eyebrow`, `heroTitle`, `heroIntro`, `bioParagraphs: string[]`, `values: string[]`, `commitments: {label,value}[]`, `siteName`, `siteTitle`, `siteDescription`, `siteAuthor`, `githubUrl`, `linkedinUrl`, `contactIntro`, `footerBlurb`, `footerCopyright`. Registered in `app.module.ts`. Pattern to follow: `src/brands/` (module/controller/service/DTO trio + colocated unit spec).
- **S2 — guards** (acceptance quote): "Sin sesión → todas las mutaciones al endpoint `profile` responden `401`; con rol no admin → `403` (guards de la issue #6, sin decorar de más)." So: NO `@Roles`/`@AllowAnonymous` on GraphQL-less public GET beyond `@AllowAnonymous()`; mutations carry `@Roles(['admin'])`.
- **S3 — public read + fallback** (acceptance quote): "Lectura pública del perfil expuesta (landing + `@AllowAnonymous`), con fallback a los valores actuales si la db no tiene fila." Default profile constant lives in the backend `profile` service (values = current site content); frontend additionally falls back to its existing constants when the API is unreachable.
- **S4 (admin panel)**: "pantalla de edición del perfil con la misma estética/convenciones de las otras pantallas (`/admin/…`). Edición no tiene que cubrir todo de una: empezar por lo estructurado (bio, valores, commitments, redes) y ver cuánto profundizar." → `/admin/perfil`, client island (`client:load`, `credentials: 'include'`, SessionGuard), form for: name, role, hero (eyebrow/title/intro), bio paragraphs (textarea, one per line), values (one per line), commitments (label/value rows), site meta (name/title/description/author), social URLs, contact intro, footer blurb/copyright. Adds entry to AdminSidebar.
- **S5 (landing consumes API)**: "`About`, `Hero`, footer y contacto leen del endpoint público" — About (name, bio, values), Hero (eyebrow, h1, intro, commitments), SiteFooter (blurb, copyright, social links), Contact (intro, social), and BaseLayout meta (title/description/site name) read profile via SSR fetch with graceful fallback to current constants. `NAV_LINKS` stays hardcoded (out of scope).
- **S6 — tests + docs** (acceptance quote): "Tests del CRUD y de la lectura pública; documentación del endpoint en `backend/README.md`." → backend unit spec for service (repo mocked) + e2e spec covering public GET and guarded mutations (401/403 in dev-auth mode); frontend verification = `astro check` + curl smoke through the running dev servers.
